# A private AI box on DigitalOcean

One `conn3x apply` creates a DigitalOcean droplet and sets it up as a small, private AI server: Ollama with an embedding model and a chat model, and Qdrant to keep the vectors in. Both listen on the droplet's loopback address only. You reach them from your own machine through an SSH tunnel, so the only port open to the internet is SSH, and only from the addresses you name.

The droplet and the software on it are planned, applied and destroyed together, and live in one state file.

## What it builds

On DigitalOcean:

- An Ubuntu 24.04 droplet, `s-2vcpu-4gb` in `lon1` by default.
- Your SSH public key, added to your account so you can log in as `root`.
- An SSH host key for the droplet, generated by the `tls` provider and installed by cloud-init. Conn3x checks the droplet against it from the very first connection, so you don't need a `known_hosts` entry.
- A cloud firewall that lets in SSH from `admin_cidrs` and nothing else.

On the droplet, five circuits:

| Circuit | What it does here |
| --- | --- |
| [circuit-baseline](https://github.com/conn3xorg/circuit-baseline) | chrony, the time zone, a few network sysctls, and key-only SSH. |
| [circuit-hardening](https://github.com/conn3xorg/circuit-hardening) | Tighter SSH crypto and kernel settings. |
| [circuit-firewall](https://github.com/conn3xorg/circuit-firewall) | ufw, denying everything incoming but SSH. |
| [circuit-ollama](https://github.com/conn3xorg/circuit-ollama) | Ollama on `127.0.0.1:11434`, with `nomic-embed-text` and `qwen2.5:0.5b`. |
| [circuit-qdrant](https://github.com/conn3xorg/circuit-qdrant) | Qdrant on `127.0.0.1:6333`, with an API key from a `random_password` resource. |

They run side by side once the droplet answers on SSH. When two of them want apt at the same time, Conn3x waits for the lock rather than failing. The droplet doesn't exist when you plan, so each host object says `os = "ubuntu"`, which stands in for the facts circuit-hardening and circuit-firewall would otherwise read from it.

There's no `depends_on` between the circuits, on purpose. It would hold back reading the droplet's facts until the apply whenever an earlier circuit had a change, and without its architecture, circuit-ollama and circuit-qdrant would plan to download their releases again.

## Why only SSH is open

The Ollama API has no authentication: anyone who can reach it can run your models, pull new ones and delete the ones you have. Qdrant has a key here, but it travels in plain HTTP. Rather than put either on the internet, both stay on `127.0.0.1`, and SSH carries your requests to them.

Two firewalls stand in front of SSH. DigitalOcean's drops anything that isn't SSH from `admin_cidrs` before it reaches the droplet, and ufw on the droplet does the same if the cloud firewall is ever removed.

circuit-hardening turns off SSH's TCP forwarding by default, which would stop the tunnel. This example sets `AllowTcpForwarding = "local"`, which allows `ssh -L` and still refuses `-R`, so nobody can use the droplet to publish a port of their own.

It also leaves `log_martians` to ufw. circuit-hardening turns it on, but ufw turns it off again each time it starts, from `/etc/ufw/sysctl.conf`, so the two would undo each other and every plan would show a change. To log martian packets, set them to `1` in that file instead.

## Before you start

- Conn3x v0.6.7 or later, which circuit-ollama v0.1.1 needs.
- A DigitalOcean [personal access token](https://docs.digitalocean.com/reference/api/create-personal-access-token/) with write access.
- An SSH key pair, `~/.ssh/id_ed25519` and `~/.ssh/id_ed25519.pub` by default.
- `curl` and `jq` for [Try it](#try-it).

## Cost

An `s-2vcpu-4gb` droplet is $24 a month, or $0.03571 an hour, at [DigitalOcean's prices](https://www.digitalocean.com/pricing/droplets) in October 2026. An hour of trying this out costs about 4 cents. Cloud firewalls are free. The droplet keeps costing money until you [remove it](#remove-it).

These two small models run on the CPU in 4 GB of memory with room to spare. A bigger chat model needs a bigger droplet: set `size`.

## Run it

```sh
export DIGITALOCEAN_TOKEN=dop_v1_...
conn3x init
conn3x apply -var 'admin_cidrs=["203.0.113.7/32"]'
```

Put your own public address in `admin_cidrs`; `curl -4 https://ifconfig.me` shows it. Type `yes` when asked.

The apply took under three minutes when we ran it in `lon1`. It downloads the Ollama release, which is 1.5 GB, and the two models, about 670 MB together, so a slower region or a bigger model takes longer. Run the same `conn3x plan -var 'admin_cidrs=...'` again afterwards and it says `No changes.`

To tag the droplet, or put it somewhere else, set `tags`, `region` or `name`:

```sh
conn3x apply -var 'admin_cidrs=["203.0.113.7/32"]' -var 'tags=["ai"]' -var region=ams3
```

## Open the tunnel

The `tunnel` output is the command to run:

```sh
$(conn3x output -raw tunnel)
```

That's `ssh -L 11434:127.0.0.1:11434 -L 6333:127.0.0.1:6333 root@<ip>`. While it's open, `localhost:11434` on your machine is Ollama on the droplet, and `localhost:6333` is Qdrant. Leave it running in its own terminal, or add `-N -f` to send it to the background.

Your `~/.ssh/known_hosts` doesn't have the droplet's key yet, so `ssh` asks you to confirm it the first time. The key it shows is the one in `tls_private_key.host`.

## Try it

In a second terminal, from this directory, with the tunnel open. Qdrant wants its key on every request:

```sh
export QDRANT_API_KEY="$(conn3x output -raw qdrant_api_key)"
```

Make a collection for `nomic-embed-text`'s 768-number vectors:

```sh
curl -s -X PUT localhost:6333/collections/notes \
  -H "api-key: $QDRANT_API_KEY" -H 'Content-Type: application/json' \
  -d '{"vectors": {"size": 768, "distance": "Cosine"}}'
```

Embed a sentence with Ollama and store it in Qdrant, with the sentence as its payload:

```sh
text="The spare key to the shed is under the blue flowerpot."
vector=$(curl -s localhost:11434/api/embed \
  -d "$(jq -n --arg t "$text" '{model: "nomic-embed-text", input: $t}')" | jq -c '.embeddings[0]')

curl -s -X PUT 'localhost:6333/collections/notes/points?wait=true' \
  -H "api-key: $QDRANT_API_KEY" -H 'Content-Type: application/json' \
  -d "$(jq -n --arg t "$text" --argjson v "$vector" '{points: [{id: 1, vector: $v, payload: {text: $t}}]}')"
```

Now ask a question in different words, and search with its embedding:

```sh
question="Where did I leave the key for the garden shed?"
query=$(curl -s localhost:11434/api/embed \
  -d "$(jq -n --arg t "$question" '{model: "nomic-embed-text", input: $t}')" | jq -c '.embeddings[0]')

curl -s -X POST localhost:6333/collections/notes/points/query \
  -H "api-key: $QDRANT_API_KEY" -H 'Content-Type: application/json' \
  -d "{\"query\": $query, \"limit\": 1, \"with_payload\": true}" | jq '.result.points[0]'
```

Qdrant finds the sentence about the flowerpot, though the question shares hardly a word with it:

```json
{
  "id": 1,
  "version": 1,
  "score": 0.8058598,
  "payload": {
    "text": "The spare key to the shed is under the blue flowerpot."
  }
}
```

To close the loop, hand what it found to the chat model, which answers from it:

```sh
found=$(curl -s -X POST localhost:6333/collections/notes/points/query \
  -H "api-key: $QDRANT_API_KEY" -H 'Content-Type: application/json' \
  -d "{\"query\": $query, \"limit\": 1, \"with_payload\": true}" | jq -r '.result.points[0].payload.text')

curl -s localhost:11434/api/generate -d "$(jq -n --arg c "$found" --arg q "$question" \
  '{model: "qwen2.5:0.5b", prompt: "Answer from this note only.\nNote: \($c)\nQuestion: \($q)", stream: false}')" | jq -r .response
```

Nothing in this section left your machine except through the tunnel, and nothing left the droplet at all.

## Remove it

```sh
conn3x destroy -var 'admin_cidrs=["203.0.113.7/32"]'
```

Type `yes`. This deletes the droplet, its cloud firewall and the SSH key it added to your account, which stops the charges. The models and vectors go with the droplet. DigitalOcean can take a few seconds to forget the SSH key: an apply straight after a destroy can fail with `SSH Key is already in use`, and works when you run it again.

The state file holds the droplet's private host key and the Qdrant key, so delete it as well:

```sh
rm -f terraform.tfstate terraform.tfstate.backup
```

For a box you keep, turn on [state encryption](https://opentofu.org/docs/language/state/encryption/) or store state where you'd store a secret.

## Inputs

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `admin_cidrs` | list(string) | Required | Addresses allowed to reach SSH, such as `["203.0.113.7/32"]`. |
| `name` | string | `"aibox"` | Name of the droplet, its SSH key and its cloud firewall. |
| `region` | string | `"lon1"` | DigitalOcean region. |
| `size` | string | `"s-2vcpu-4gb"` | Droplet size. |
| `tags` | list(string) | `[]` | Tags for the droplet. |
| `ssh_public_key_file` | string | `"~/.ssh/id_ed25519.pub"` | Public key added to your account and the droplet. |
| `ssh_private_key_file` | string | `"~/.ssh/id_ed25519"` | Its private half, which Conn3x logs in with. |

## Outputs

| Name | Description |
| --- | --- |
| `ip` | The droplet's public IPv4 address. |
| `tunnel` | The `ssh -L` command that opens the tunnel. |
| `qdrant_api_key` | Qdrant's API key. Sensitive: `conn3x output -raw qdrant_api_key` shows it. |

## Tested on

Applied with Conn3x v0.6.6 in `lon1`, from an empty state: 101 resources in 2 minutes 36 seconds, and the second plan said `No changes.` The droplet's host key matched `tls_private_key.host`. Ollama and Qdrant listened on `127.0.0.1` only, ports 11434, 6333 and 6334 didn't answer from outside, and Qdrant answered a request without the key with `401`. Every command in [Try it](#try-it) ran as written through the tunnel, in zsh; the search scored 0.806 and `qwen2.5:0.5b` answered "under the blue flowerpot". After a reboot, Ollama, Qdrant and ufw came back, the plan had no changes, and the search found the same point again. `conn3x destroy` removed the droplet, the firewall and the SSH key in 41 seconds.
